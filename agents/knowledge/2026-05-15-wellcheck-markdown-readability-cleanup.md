## wellcheck Markdown readability cleanup — 2026-05-15

**컨텍스트**: `wellcheck-plugins` 저장소에서 Markdown 가독성 리뷰 보고서를 기준으로 루트 문서, 핵심 workflow SKILL, support SKILL, reference/persona 문서를 정리했다. 사용자는 `main` 최신 상태에서 새 브랜치를 만들고, 커밋 단위를 분리해 적용하길 요청했다.

**핵심 결정**: 긴 문서를 전면 재작성하지 않고, 상단에 `Quick Guide`, `Default Flow`, 짧은 역할 설명을 일관되게 추가하는 방식으로 정리했다. 이렇게 하면 의미 drift 위험은 낮추면서도 "첫 화면에서 파일 목적이 보이는가" 라는 가독성 문제를 빠르게 해결할 수 있다.

**발견**: 문서 가독성 개선은 내용 삭제보다 상단 정보 구조 정리가 효과가 컸다. 특히 workflow SKILL 계열은 `입력 / 산출물 / 다음 단계`만 상단에 드러내도 긴 본문 독해 비용이 크게 줄었다.

**실수**: 첫 시도에서 너무 큰 패치를 한 번에 적용하려다 일부 파일의 실제 도입 문구와 맞지 않아 패치가 실패했다. 긴 Markdown 일괄 수정은 파일군을 묶되, 각 파일의 실제 상단 문구를 다시 확인한 뒤 패치해야 안전하다.

**다음 번엔**: Markdown 대량 정리는 "루트 문서 → 긴 workflow → 긴 reference → 짧은 support" 순으로 자르고, 각 묶음을 즉시 커밋하는 방식이 가장 안정적이다. 또 보고서 기반 실행 작업은 남은 대상 수를 스크립트로 계속 계산하면 누락 없이 끝내기 쉽다.
