# AI Slop GC (Garbage Collection)

AI가 생성한 코드의 나쁜 패턴을 탐지하고 정리하는 주기적 검토 워크플로우.

## 언제 실행하나

- **주기적**: 매주 한 번 (금요일 또는 스프린트 마무리)
- **이벤트 기반**: 큰 기능 완성 후, PR 머지 전
- **수동 호출**: `post-write-quality` 훅에서 슬롭 경고가 반복 감지될 때

## 4단계 워크플로우

### Phase 1: 범위 설정

검토할 범위를 사용자에게 확인한다:

```
최근 변경된 파일을 검토할까요, 아니면 특정 디렉토리/기능 단위로 검토할까요?
[옵션]
a) 최근 N일 이내 변경된 파일 (git log 기반)
b) 특정 디렉토리
c) 이번 PR/브랜치 변경 파일
```

---

### Phase 2: 패턴 탐지

아래 AI 슬롭 패턴을 파일별로 스캔한다:

#### 🗑️ 불필요한 코드
- **자명한 주석**: 코드가 이미 설명하는 내용을 그대로 반복하는 주석
  ```python
  # Increment counter by 1  ← 제거 대상
  counter += 1
  ```
- **죽은 코드**: 호출되지 않는 함수, 참조되지 않는 변수
- **과도한 TODO/FIXME**: 구현 없이 남겨진 플레이스홀더

#### 🔀 과도한 복잡도
- **불필요한 추상화**: 한 곳에서만 호출되는 단순 래퍼 함수
- **과도한 중첩**: 6단계 이상 들여쓰기
- **God function**: 50줄 이상의 단일 함수

#### 🔁 중복 패턴
- **복사-붙여넣기**: 3개 이상 파일에서 동일한 20줄+ 블록
- **일관성 없는 네이밍**: 같은 개념에 다른 이름 사용 (e.g., `user_id` vs `userId` vs `uid`)

#### 🛡️ 과잉 방어 코드
- **불가능한 케이스 처리**: 내부 코드의 타입을 이미 보장하는 검증
- **과도한 에러 핸들링**: 발생할 수 없는 예외 처리

---

### Phase 3: 정리 제안

탐지된 패턴을 표로 정리해 사용자에게 보여준다:

```
## 탐지된 패턴

| 파일 | 패턴 | 심각도 | 제안 |
|------|------|--------|------|
| src/user.py | 자명한 주석 7개 | 낮음 | 주석 제거 |
| src/utils.py | 래퍼 함수 3개 | 중간 | 인라인으로 병합 |
| src/api.py | God function (72줄) | 높음 | 분리 필요 |
```

심각도별 우선순위:
- **높음**: 즉시 정리 (복잡도, God function)
- **중간**: 이번 주 내 정리 (중복, 추상화)
- **낮음**: 다음 주기에 정리 (주석, 네이밍)

---

### Phase 4: 적용

사용자 승인 후 파일별로 정리를 적용한다.

**적용 원칙:**
- 기능 변경 없이 구조만 개선한다
- 각 정리 단위는 독립적으로 커밋한다 (`refactor: remove AI slop in X`)
- 불확실한 경우 삭제보다 주석 처리 후 사용자에게 확인

완료 후:
```
✅ Code GC 완료
- 검토 파일: N개
- 정리된 패턴: [목록]
- 다음 GC 권장 시점: [날짜 또는 이벤트]
```
