# Commit IDS

사용자가 명시적으로 커밋을 원하거나, 팀 규칙에 맞는 커밋 메시지가 필요할 때 이 스킬을 사용한다.

## 실행 절차

1. 스테이징된 변경사항만 확인한다.
2. `git commit -a`나 `git add .`처럼 범위를 넓히는 방식은 사용하지 않는다.
3. `git status`로 실제 커밋 대상 파일을 먼저 명확히 확인한다.
4. 현재 브랜치 이름에서 Jira 티켓을 추출할 수 있으면 반영한다.
5. 아래 형식으로 커밋 메시지를 작성한다.

```text
[JIRA-ID] type: subject

- 변경 요약
- 변경 요약
```

Jira 티켓이 없으면 대괄호 접두어를 생략한다.

## 커밋 규칙

- 커밋에는 스테이징된 변경사항만 포함한다.
- 제목은 간결하게 작성하고 가능하면 50자 안팎으로 유지한다.
- 본문에는 무엇을 왜 바꿨는지 적고, 필요하면 불릿을 사용한다.
- 저장소 관례가 다르지 않다면 제목과 본문은 한국어를 우선한다.
- 타입은 `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore` 중 하나를 사용한다.

## Jira 추출 규칙

현재 브랜치 이름에서 `feature/`, `feat/`, `fix/`, `chore/` 같은 접두어를 제거한 뒤 Jira 티켓을 추출한다.

예시:

- `feature/MCCWC-1234-login` -> `MCCWC-1234`
- `fix/PROJ-567-null-check` -> `PROJ-567`
- `chore/update-docs` -> Jira 접두어 없음

## 실제 커밋 시 동작

사용자가 실제 커밋까지 요청한 경우:

1. `git status --short --branch`로 스테이징된 파일이 있는지 확인한다.
2. `git diff --cached --stat`와 필요시 `git diff --cached`로 변경 내용을 검토한다.
3. 스테이징된 변경사항 기준으로 메시지를 작성한다.
4. 명시적인 메시지로 커밋하고, 스테이징된 변경사항 외에는 포함하지 않는다.

사용자가 메시지만 원하면 `git commit`은 실행하지 않고 메시지만 제공한다.

## 안전 점검

- 스테이징된 파일이 없으면 커밋할 내용이 없다고 알리고 멈춘다.
- 관련 없는 변경사항이 함께 스테이징되어 있으면 커밋 전에 먼저 알린다.
- 사용자가 명시적으로 요청하지 않으면 unstaged 파일이나 untracked 파일을 포함하지 않는다.

## 예시

```text
[MCCWC-8342] feat: 신청 관리 페이지 추가

- 신청 관리 목록 조회 API를 연동함
- 탭 레이아웃과 페이지 라우팅을 연결함
```

```text
docs: 커밋 메시지 규칙 문서 업데이트

- 제목과 본문 작성 규칙을 정리함
- Jira 티켓 추출 예시를 보강함
```
