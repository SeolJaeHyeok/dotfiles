# AWS 네트워크 서비스 레퍼런스

## VPC (Virtual Private Cloud)

AWS에서 나만의 가상 네트워크. 모든 AWS 리소스는 VPC 안에 존재한다.

### 초보자 권장 구성

```
VPC (10.0.0.0/16) — 65,536개 IP
├── 퍼블릭 서브넷 A (10.0.1.0/24) — 인터넷 접근 가능, AZ-a
├── 퍼블릭 서브넷 B (10.0.2.0/24) — 인터넷 접근 가능, AZ-c
├── 프라이빗 서브넷 A (10.0.11.0/24) — 인터넷 접근 불가, AZ-a
└── 프라이빗 서브넷 B (10.0.12.0/24) — 인터넷 접근 불가, AZ-c
```

- **퍼블릭 서브넷**: 웹서버, ALB (인터넷에서 접근 필요한 것)
- **프라이빗 서브넷**: DB, 내부 서비스 (인터넷에서 접근하면 안 되는 것)
- **2개 AZ**: 하나가 장애나도 서비스 유지 (고가용성)

### 자주 하는 실수
- 모든 리소스를 퍼블릭 서브넷에 배치 → DB는 반드시 프라이빗에
- NAT Gateway 비용 간과 → 월 ~$35 + 데이터 처리 비용. 개발 환경에서는 NAT Instance(t3.nano ~$4)로 대체 가능
- CIDR 범위를 너무 작게 설정 → 나중에 서브넷 추가 어려움. /16으로 시작 권장

### 비용
- VPC 자체: 무료
- NAT Gateway: ~$35/월 + $0.059/GB
- VPC Endpoints: Gateway 타입 무료 (S3, DynamoDB), Interface 타입 ~$8/월

## ALB (Application Load Balancer)

HTTP/HTTPS 트래픽을 여러 서버에 분산하는 로드밸런서.

### 초보자 권장 설정
- 타입: Application (HTTP/HTTPS용). Network LB는 TCP/고성능 전용
- 리스너: HTTPS(443) → 타겟 그룹
- 타겟 그룹: EC2 인스턴스 또는 ECS 태스크
- 헬스 체크: `/health` 경로, 30초 간격

### HTTPS 설정
1. ACM(AWS Certificate Manager)에서 무료 SSL 인증서 발급
2. Route53에서 도메인 검증 (DNS 레코드 추가)
3. ALB 리스너에 인증서 연결
4. HTTP(80) → HTTPS(443) 리다이렉트 규칙 추가

### 비용
- ALB: ~$18/월 (고정) + LCU(사용량) 기반 추가
- ACM 인증서: 무료

## Route53

AWS의 DNS 서비스. 도메인을 AWS 리소스에 연결한다.

### 초보자 권장 설정
- 호스팅 영역: 도메인당 1개 생성
- A 레코드 (별칭): ALB 또는 CloudFront를 가리킴
- TTL: 300초 (5분) — 변경 사항이 빠르게 반영

### 비용
- 호스팅 영역: $0.50/월
- 쿼리: 100만 쿼리당 $0.40
- 도메인 등록: .com $13/년, .io $39/년

## Security Group

가상 방화벽. 인바운드(들어오는)/아웃바운드(나가는) 트래픽을 제어한다.

### 초보자 권장 규칙

**웹서버용:**
| 방향 | 포트 | 소스 | 용도 |
|------|------|------|------|
| 인바운드 | 80 | 0.0.0.0/0 | HTTP |
| 인바운드 | 443 | 0.0.0.0/0 | HTTPS |
| 인바운드 | 22 | 내 IP만 | SSH |
| 아웃바운드 | 전체 | 0.0.0.0/0 | (기본값) |

**DB용:**
| 방향 | 포트 | 소스 | 용도 |
|------|------|------|------|
| 인바운드 | 3306/5432 | 웹서버 SG | MySQL/PostgreSQL |
| 아웃바운드 | 전체 | 0.0.0.0/0 | (기본값) |

### 핵심 원칙
- **소스에 IP 대신 Security Group ID를 사용한다** — "이 SG에 속한 리소스만 접근 가능" 방식이 더 안전하고 유연
- **SSH(22)는 절대 0.0.0.0/0으로 열지 않는다** — Session Manager 사용 권장
