# AWS 스토리지/DB 서비스 레퍼런스

## 서비스 선택 가이드

| 상황 | 추천 서비스 | 이유 |
|------|-----------|------|
| 파일/이미지 저장 | S3 | 무제한 용량, 저렴, 정적 호스팅 가능 |
| 관계형 데이터 (SQL) | RDS | 관리형 MySQL/PostgreSQL |
| Key-Value / 유연한 스키마 | DynamoDB | 서버리스, 자동 확장 |
| 캐싱 | ElastiCache | Redis/Memcached 관리형 |
| 검색 | OpenSearch | 전문 검색, 로그 분석 |

## S3 (Simple Storage Service)

### 초보자 권장 설정
- 버킷 이름: 전 세계에서 고유해야 함 (예: `myapp-prod-assets-2026`)
- 리전: ap-northeast-2 (서울)
- 퍼블릭 액세스: **모두 차단** (기본값 유지)
- 버전 관리: 프로덕션이면 활성화 (실수로 삭제 방지)
- 암호화: SSE-S3 (기본 활성화됨)

### 정적 웹사이트 호스팅
S3 + CloudFront 조합이 가장 저렴한 정적 사이트 호스팅 방법.
1. S3 버킷에 빌드 파일 업로드
2. CloudFront 배포 생성 (S3를 오리진으로)
3. OAC(Origin Access Control)로 S3 직접 접근 차단
4. Route53에서 도메인 연결

### 자주 하는 실수
- 버킷을 퍼블릭으로 열어두기 → 데이터 유출 사고의 가장 흔한 원인
- 수명 주기 규칙 미설정 → 오래된 파일이 계속 쌓여 비용 증가
- 대용량 파일 업로드 시 multipart upload 미사용 → 실패 시 처음부터 다시

### 비용
- 저장: $0.025/GB/월 (Standard)
- 요청: GET 1,000건당 $0.0004, PUT 1,000건당 $0.005
- 데이터 전송(아웃): 처음 100GB/월 무료 → $0.126/GB

## RDS (Relational Database Service)

### 초보자 권장 설정
- 엔진: PostgreSQL 16 (범용, 커뮤니티 활발) 또는 MySQL 8
- 인스턴스: `db.t3.micro` (프리 티어) 또는 `db.t3.small`
- 스토리지: gp3 20GB, 자동 확장 활성화
- Multi-AZ: 프로덕션이면 활성화, 개발이면 비활성화 (비용 2배)
- 자동 백업: 7일 보존 (기본값 유지)
- 퍼블릭 액세스: **비활성화** (프라이빗 서브넷에 배치)

### Aurora vs RDS
| 기준 | RDS | Aurora |
|------|-----|--------|
| 비용 | 저렴 | ~20% 비쌈 |
| 성능 | 좋음 | MySQL 5배, PostgreSQL 3배 |
| 가용성 | Multi-AZ 필요 | 기본 제공 |
| 추천 대상 | 소규모, 비용 우선 | 중대규모, 성능 우선 |

### 자주 하는 실수
- 퍼블릭 서브넷에 DB 배치 → 보안 위험. 프라이빗 서브넷 필수
- 파라미터 그룹 미설정 → 기본값이 한국어/UTF-8에 맞지 않을 수 있음
- 스냅샷 정리 안 함 → 수동 스냅샷은 자동 삭제 안 됨, 비용 누적

### 비용 (서울 리전)
| 타입 | vCPU | 메모리 | 월 비용 | 프리 티어 |
|------|------|--------|--------|---------|
| db.t3.micro | 2 | 1GB | ~$18 | 12개월 750시간/월 |
| db.t3.small | 2 | 2GB | ~$36 | X |
| db.t3.medium | 2 | 4GB | ~$72 | X |

## DynamoDB

### 초보자 권장 설정
- 용량 모드: **온디맨드** (시작 시 — 트래픽 예측 불필요)
- 파티션 키 설계가 핵심 — 균등 분산되는 키 선택 (예: userId, orderId)
- GSI(글로벌 보조 인덱스)는 필요할 때만 추가 (비용 추가)

### RDS vs DynamoDB
| 기준 | RDS | DynamoDB |
|------|-----|----------|
| 데이터 모델 | 테이블/관계 | Key-Value/Document |
| 쿼리 유연성 | SQL (자유롭게) | 파티션 키 기반 (제한적) |
| 스케일링 | 수직 (인스턴스 변경) | 자동 수평 확장 |
| 관리 부담 | 중간 | 거의 없음 |
| 적합한 경우 | 복잡한 관계, JOIN 필요 | 단순 조회, 대규모 트래픽 |

### 비용
- 온디맨드: 읽기 100만 건 $1.25, 쓰기 100만 건 $6.25
- 저장: $0.25/GB/월
- 프리 티어: 25GB 저장 + 읽기 25/쓰기 25 용량 단위 (영구)
