# Phase 1: 이슈 분석 및 기여 전략 수립

## 절차

### 1. Context 확보
프로젝트 루트의 `CONTRIBUTING.md`를 분석하여 파악:
- 코딩 컨벤션
- 브랜치 전략
- 커밋 메시지 규칙
- PR 제출 절차

### 2. 이슈 탐색

**이슈가 사용자에게 제공된 경우:**
- 해당 이슈를 직접 분석

**이슈가 없는 경우:**
- 해당 프로젝트 이슈 목록에서 `good first issue` 또는 `help wanted` 라벨이 붙은 이슈 탐색
- 최근 3개월 내 활성화된 이슈 우선 선정
- 복수의 후보를 선정하여 다음 단계로 진행

### 3. 중복 체크
관심 이슈를 찾으면, 해당 프로젝트의 PR 목록에서 해당 이슈 번호를 참조(mention)하는 열린 PR이 있는지 확인해. (중복 작업 방지)

### 4. Agent-Council 소집
선정된 이슈들에 대해 `agent-council` 스킬을 호출하여 평가:
- 해결 가능성
- 난이도
- 영향도 (기여 가치)

평가 후 가장 적합한 이슈 1개를 선택.

### 5. 기여 전략 보고서 작성
아래 항목을 포함한 보고서를 작성:

```
## 기여 전략 보고서

### 선정 이슈
- 이슈 번호 및 제목
- 이슈 URL
- 선정 이유

### 이슈 유형
- 유형: bug | feature | enhancement | docs | refactor
  (Phase 2에서 워크플로우 분기 기준으로 사용된다)

### 프로젝트 컨벤션 요약
- 브랜치 네이밍 규칙
- 커밋 메시지 형식
- 코딩 스타일 주요 규칙

### 구현 전략
- 변경이 필요한 파일/모듈 (예상)
- 접근 방법
- 예상 난이도

### 리스크
- 잠재적 Side Effect
- 주의해야 할 의존성
```

### 6. 사용자 승인 요청
보고서를 제출하고 사용자의 승인을 받은 후 Phase 2로 진행.
