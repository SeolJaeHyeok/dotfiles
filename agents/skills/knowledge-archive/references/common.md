# Knowledge Archive Common Flow

## 실행 조건

- `feature-dev` Step 5
- `bug-fix` Phase 5 마무리
- 사용자가 "기억해줘", "아카이빙해줘"라고 말할 때

## Stage 0: Quality Gate

추출 전에 아래 3가지 질문을 확인한다. **하나라도 해당하면 저장하지 않는다.**

| 질문 | 해당하면 |
|---|---|
| 5분 안에 구글링으로 찾을 수 있는가? | 저장 안 함 |
| 이 코드베이스/프로젝트에 한정된 내용이 아닌가? | 저장 안 함 |
| 실제 디버깅·분석 노력 없이 알 수 있었던 내용인가? | 저장 안 함 |

3가지 모두 통과한 항목만 Stage 1로 넘긴다.

## Stage 1: 추출

이번 작업에서 아래 항목을 추출한다.

```text
[결정] 어떤 접근법을 선택했고 왜 다른 접근법을 선택하지 않았는가?
[발견] 예상과 달랐던 것은 무엇인가?
[실수] 잘못 판단한 부분과 그 원인은?
[패턴] 재사용 가능한 패턴이나 컨벤션은? (코드 스니펫이 아닌 사고 방식·원칙으로 기록한다)
[경고] 다음에 이 영역을 건드릴 때 반드시 알아야 할 것은?
```

항목이 없으면 생략한다. 억지로 채우지 않는다.

## Stage 2: 저장

host adapter에 정의된 저장 방식을 따른다.

- `ce_workflow: available` 이고 `ce:compound`를 실제로 사용할 수 있으면 그 경로를 우선 사용한다.
- 그렇지 않으면 `~/.agents/knowledge/README.md`의 형식대로 markdown 파일을 만든다.

저장 포맷:

```markdown
## [기능/버그명] — [날짜]

**컨텍스트**: [어떤 작업이었는가]

**핵심 결정**: [선택한 접근법과 이유]

**발견**: [예상과 달랐던 것]

**실수**: [잘못 판단한 부분과 원인]

**다음 번엔**: [이 영역을 다시 건드릴 때 알아야 할 것]
```

## Stage 3: Harness 반영 여부 확인

저장된 내용 중 규칙이나 워크플로우에 반영해야 할 패턴이 있으면 `harness-improve`를 실행한다.

없으면 아래 형식으로 완료를 선언한다.

```markdown
✅ 지식 아카이빙 완료
- 저장된 항목: [목록]
- Harness 반영: 있음 / 없음
```
