# Find Wiki

이 스킬은 사용자의 질문에 답하기 전에 Obsidian Vault를 먼저 검색하고, 부족한 부분만 신뢰 가능한 외부 자료로 보강해 답변하게 한다.

## 목표

- 답변 전에 항상 Vault를 먼저 확인한다.
- 기억이나 일반 지식으로 바로 답하지 않는다.
- Vault에 없는 내용은 외부 근거를 확인한 뒤 답한다.
- 가치 있는 외부 자료는 사용자 승인 후 LLM Wiki에 통합한다.

Vault 루트:

`/Users/seoljaehyeok/Documents/Obsidian Vault`

## 자동 호출 가드레일

사용자가 `/find-wiki` 또는 `find-wiki`를 직접 쓰지 않아도 아래 조건이면 이 스킬을 먼저 적용한다.

- 현재 작업 중인 프로젝트가 개인 위키, Obsidian Vault, LLM Wiki, 지식 베이스, 노트 저장소와 연결돼 있다.
- 현재 프로젝트의 `AGENTS.md`, `CLAUDE.md`, 규칙 문서, MOC, Reference 구조가 Vault 검색 기반 답변을 요구한다.
- 사용자가 아래와 같은 질문을 한다.
  - `뭐야`, `왜`, `어떻게`, `차이`, `정리해줘`, `설명해줘`
  - 과거에 정리해둔 내용, 예전 노트, 개발 기록, 회의록, 레퍼런스, 프롬프트, 워크플로우를 찾는 질문
  - AI, 개발, 회고, 트러블슈팅, 비교, 개념 요약처럼 Vault에 있을 가능성이 높은 질문

현재 작업 디렉터리가 Vault가 아니어도, 사용자의 질문이 개인 지식 베이스에서 답을 찾는 성격이면 먼저 Vault를 짧게 검색한다.

## 질의 원칙

1. 질문이 들어오면 먼저 Vault 안에 관련 노트가 있는지 찾는다.
2. raw source 전체를 바로 뒤지지 말고, 정리된 Wiki와 MOC를 먼저 본다.
3. Vault 정보만으로 충분하면 그 근거만으로 답한다.
4. Vault 정보가 부족하면 외부 근거를 확인해 보강한다.
5. 답변에 쓴 근거 노트는 최대 3개까지 경로로 인용한다.
6. 외부 자료를 쓴 경우 그 사실을 명시한다.
7. 외부 자료가 장기적으로 가치 있으면 Vault에 ingest할지 사용자에게 묻는다.

## 우선 검색 순서

1. `MOC - *.md`
2. `개발 기록/`
3. `Reference/`
4. 그 외 질문과 직접 관련된 위키형 노트
5. 부족할 때만 export, raw source, html 같은 원문성 자료

## 검색 전략

가능하면 빠른 검색부터 시작한다.

권장 명령:

- `rg --files`
- `rg -n`
- `sed -n`

기본 흐름:

1. 질문 키워드로 관련 제목, 폴더, MOC를 찾는다.
2. 관련 MOC가 있으면 먼저 읽는다.
3. 가장 유력한 노트 1~3개를 먼저 읽는다.
4. 답이 부족할 때만 범위를 넓힌다.

## Vault에 답이 없을 때

Vault에 충분한 정보가 없으면 추측하지 말고 외부 근거를 찾는다.

우선순위:

1. 공식 문서
2. 1차 출처
3. Context7
4. 웹 검색
5. 필요 시 실행 가능한 도구나 검증 수단

원칙:

- 최신성이 중요한 주제는 반드시 외부 확인 후 답한다.
- 가능하면 둘 이상의 신뢰 가능한 출처를 교차 확인한다.
- 불확실하면 불확실하다고 명시한다.
- 외부 자료를 바탕으로 답할 때는 링크나 출처를 함께 제시한다.

외부 자료를 사용했다면 답변 뒤에 아래 질문을 한다.

`이 내용을 Vault에 정리해서 ingest할까요?`

## 외부 자료 ingest 원칙

사용자가 승인한 경우에만 Vault에 적재한다.

ingest는 단순 저장이 아니라 LLM Wiki 통합 작업을 의미한다.

수행 내용:

1. 자료의 핵심 내용을 요약한다.
2. 기존 유사 노트를 먼저 검색한다.
3. 새 노트 생성보다 기존 Wiki/MOC 갱신을 우선 검토한다.
4. 필요하면 canonical note를 정하고, 중복 노트는 만들지 않도록 연결 구조를 제안한다.
5. 관련 `[[wikilink]]`와 MOC 연결을 보강한다.
6. 새 노트를 만들 경우 Vault 규칙에 맞는 위치와 frontmatter를 사용한다.
7. raw source와 wiki note의 역할을 분리한다.
8. 어떤 파일을 만들거나 수정할지 먼저 제안한 뒤 진행한다.

## 더 깊게 탐색하도록 돕기

답변을 마친 뒤, 관련 지식이나 다음 탐색 후보가 있으면 사용자가 더 파고들지 선택할 수 있게 제안한다.

제안 예시:

- `이 주제와 연결된 관련 노트도 같이 볼까요?`
- `이 개념의 배경이나 비교 주제까지 더 탐색할까요?`
- `관련된 실전 사례나 트러블슈팅 기록도 찾아볼까요?`
- `외부 자료까지 확장해서 더 깊게 조사할까요?`

사용자가 원하면 아래 중 하나로 확장한다.

- Vault 내부 연관 노트 확장 탐색
- 외부 자료 기반 심화 탐색
- 조사 결과를 새 wiki 초안이나 기존 노트 보강안으로 정리

## 답변 방식

답변할 때는 아래 순서를 따른다.

1. 핵심 답변을 먼저 짧게 준다.
2. Vault 근거가 있으면 근거 노트 경로를 최대 3개까지 제시한다.
3. 외부 자료를 썼다면 그 사실과 출처를 명시한다.
4. Vault에 없는 내용을 쓰는 경우 아래 문구를 명시한다.
   - `볼트에 해당 내용 없어 외부 자료와 일반 지식을 함께 사용해 답합니다`
5. 끝에 아래 섹션을 붙인다.
   - `관련 있을 수 있는 노트:`
6. 필요하면 심화 탐색 여부를 묻는다.
7. 외부 자료가 유의미하면 ingest 여부를 묻는다.

## 좋은 답변의 기준

좋은 답변은 다음 조건을 만족한다.

- Vault 검색 결과를 바탕으로 답한다.
- Vault 지식과 외부 지식을 구분한다.
- MOC와 정리된 위키 노트를 먼저 본다.
- 외부 자료는 신뢰 가능한 출처로 검증한다.
- 불필요하게 Vault 전체를 과탐색하지 않는다.
- 근거 노트 경로와 외부 출처를 남긴다.
- 사용자가 더 깊이 탐색할 기회를 제공한다.
- 가치 있는 외부 자료는 ingest 후보로 연결한다.

나쁜 답변은 다음과 같다.

- Vault 검색 없이 바로 기억으로 답한다.
- raw export를 MOC보다 먼저 읽는다.
- 외부 정보를 검증 없이 섞는다.
- 일반 지식을 Vault 근거처럼 말한다.
- 근거 노트나 출처를 남기지 않는다.
- 좋은 외부 자료를 찾고도 ingest 기회를 놓친다.

## 관련 노트가 충분하지 않을 때

관련 노트가 충분하지 않으면 다음 순서를 따른다.

1. Vault에 충분한 내용이 없다고 명시한다.
2. 외부 근거를 찾아 보강 답변한다.
3. 사용자가 원하면 더 깊은 탐색을 진행한다.
4. 가치 있는 자료라면 Vault ingest 여부를 묻는다.
